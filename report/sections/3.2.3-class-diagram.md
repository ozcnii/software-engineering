## 3.2.3 Диаграмма классов

В соответствии со спецификацией, приведенной в п. 2.4.6, и с учетом выбранного языка программирования разработана диаграмма классов системы «Лабиринт» на этапе реализации, приведенная на рисунке N.

![Рисунок N – Описание классов системы на этапе реализации](../../diagrams/class/class-diagram.png)

Рисунок N – Описание классов системы на этапе реализации

Назначение классов системы приведено в таблице N.

| Название класса | Назначение |
| --- | --- |
| User | Учетная запись пользователя с ролью администратора или игрока |
| LabyrinthsController | Контроллер HTTP-запросов клиента к серверной части |
| LabyrinthsService | Сервис прикладной логики операций с лабиринтами |
| LabyrinthGame | Доменный класс лабиринта, хранит параметры и управляет генерацией и решением |
| Maze | Сетка клеток лабиринта и операции расстановки входа и выхода |
| Coordinate | Координаты клетки лабиринта (строка и столбец) |
| SolutionPath | Результат автоматического решения лабиринта (алгоритм, путь, число шагов) |
| GridValidation | Проверки размеров, координат, толстостенности и связности сетки |
| PrimGenerator | Генерация лабиринта алгоритмом Прима |
| KruskalGenerator | Генерация лабиринта алгоритмом Краскала |
| BfsSolver | Поиск кратчайшего пути волновым алгоритмом |
| RightHandSolver | Поиск пути методом правой руки |

Таблица N – Назначение классов системы

Диаграмма отражает основные классы и модули реализации серверной части. `LabyrinthsController` принимает HTTP-запросы клиента и передает их в `LabyrinthsService`. Сервис выполняет операции получения списка лабиринтов, генерации, создания, удаления, проверки названия и решения лабиринта.

Основная доменная логика сосредоточена в `LabyrinthGame`. Этот класс хранит параметры лабиринта, управляет генерацией и вызывает алгоритмы решения. Класс `Maze` содержит сетку клеток и операции установки входа и выхода. Для представления координат используется класс `Coordinate`.

Результат автоматического решения формируется классом `SolutionPath`. Генерация лабиринта выполняется модулями `PrimGenerator` и `KruskalGenerator`. Поиск пути выполняется модулями `BfsSolver` и `RightHandSolver`. Проверки размеров, координат входа и выхода, толстостенности, связности проходов и отсутствия изолированных областей вынесены в `GridValidation`.
