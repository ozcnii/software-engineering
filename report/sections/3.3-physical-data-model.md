## 3.3 Физическая модель данных

Физическое проектирование базы данных является этапом, на котором логическая структура данных приводится к виду, пригодному для реализации в конкретной системе управления базами данных. Физическая модель содержит имена таблиц и столбцов, типы данных, первичные и внешние ключи, индексы и ограничения.

В системе «Лабиринт» база данных реализуется в PostgreSQL. Описание структуры базы данных задано в схеме Prisma, на основании которой формируется физическая модель. Физическая модель данных системы приведена на рисунке N.

![Рисунок N – Физическая модель данных системы](../../diagrams/data/physical-data-model.png)

Рисунок N – Физическая модель данных системы

В базе данных используются две основные таблицы: `User` и `Labyrinth`. Таблица `User` хранит учетные записи пользователей, а таблица `Labyrinth` хранит созданные лабиринты и связана с пользователем, который их создал.

Таблица N – Сущность `User`

| Атрибут | Тип | Ограничение | Описание |
| --- | --- | --- | --- |
| id | String | PK, uuid | Уникальный идентификатор пользователя |
| login | String | unique, not null | Логин пользователя |
| passwordHash | String | not null | Хеш пароля пользователя |
| role | UserRole | not null | Роль пользователя |
| createdAt | DateTime | not null | Дата и время создания учетной записи |

Таблица N – Сущность `Labyrinth`

| Атрибут | Тип | Ограничение | Описание |
| --- | --- | --- | --- |
| id | String | PK, uuid | Уникальный идентификатор лабиринта |
| name | String | not null | Название лабиринта |
| width | Int | not null | Ширина сетки лабиринта |
| height | Int | not null | Высота сетки лабиринта |
| theme | LabyrinthTheme | not null | Тема оформления лабиринта |
| generationAlgorithm | GenerationAlgorithm | not null | Алгоритм генерации лабиринта |
| entryMode | EntryMode | not null | Способ расстановки входа и выхода |
| grid | Json | not null | Сетка лабиринта |
| createdById | String | FK, not null | Идентификатор пользователя, создавшего лабиринт |
| createdAt | DateTime | not null | Дата и время создания лабиринта |
| deletedAt | DateTime? | nullable | Дата и время мягкого удаления лабиринта |

Таблица `Labyrinth` содержит внешний ключ `createdById`, который ссылается на первичный ключ `id` таблицы `User`. Между таблицами установлена связь один-ко-многим: один пользователь может создать несколько лабиринтов, но каждый лабиринт связан только с одним создателем.

Для таблицы `User` задан уникальный индекс по полю `login`, что исключает регистрацию двух пользователей с одинаковым логином. Для таблицы `Labyrinth` заданы индексы по полю `createdById` и по набору полей `deletedAt`, `createdAt`, `id`. Индекс `createdById` ускоряет выборку лабиринтов по пользователю, а составной индекс используется для получения активных лабиринтов с учетом мягкого удаления и сортировки по дате создания.

В модели используются перечисления, приведенные в таблицах N-N.

Таблица N – Перечисление `UserRole`

| Значение | Описание |
| --- | --- |
| ADMIN | Администратор |
| PLAYER | Игрок |

Таблица N – Перечисление `LabyrinthTheme`

| Значение | Описание |
| --- | --- |
| WINTER | Зимняя тема |
| SUMMER | Летняя тема |
| AUTUMN | Осенняя тема |
| SPRING | Весенняя тема |

Таблица N – Перечисление `GenerationAlgorithm`

| Значение | Описание |
| --- | --- |
| PRIM | Генерация алгоритмом Прима |
| KRUSKAL | Генерация алгоритмом Краскала |

Таблица N – Перечисление `EntryMode`

| Значение | Описание |
| --- | --- |
| AUTO | Автоматическая расстановка входа и выхода |
| MANUAL | Ручная расстановка входа и выхода |

Поле `deletedAt` используется для мягкого удаления лабиринта. При удалении запись не удаляется физически из базы данных, а получает дату удаления. Это позволяет скрывать удаленные лабиринты из активных списков и при необходимости сохранять историю созданных записей.
