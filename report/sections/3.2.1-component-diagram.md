## 3.2.1 Диаграмма компонентов

Диаграмма компонентов UML относится к диаграммам физического уровня и предназначена для представления программных компонентов системы и зависимостей между ними. На такой диаграмме могут показываться исполняемые компоненты, исходные модули, библиотеки, интерфейсы, порты и зависимости. Для уточнения типа компонента используются стереотипы, например `<<executable>>`, `<<library>>` и `<<source>>` [?].

Для приложения «Лабиринт» диаграмма компонентов отражает клиентскую часть, серверную часть, общий контракт типов и слой данных. Клиентская часть представлена React/Vite-приложением, функциональными зонами `features/auth`, `features/admin`, `features/player` и API-слоем `shared/api`. API-слой выполняет REST JSON-запросы к серверному приложению `NestJS backend API`.

Серверная часть построена на NestJS и включает корневое backend-приложение, модули `AuthModule`, `UsersModule`, `LabyrinthsModule`, `GenerationModule` и `SolvingModule`. Модуль аутентификации использует модуль пользователей, а модуль работы с лабиринтами использует модули генерации и решения. Доступ к данным выполняется через `Prisma Client`, который обращается к PostgreSQL. Общие TypeScript-типы домена и API вынесены в `shared/types` и используются клиентской и серверной частями как контракт данных.

На рисунке N представлена диаграмма компонентов системы.

Рисунок N – Диаграмма компонентов системы

В таблице N приведено назначение основных компонентов системы.

| Название компонента | Стереотип | Назначение компонента | Подсистема |
| --- | --- | --- | --- |
| React/Vite frontend | `<<executable>>` | Пользовательский интерфейс приложения | Клиентская часть |
| features/auth | `<<source>>` | Формы входа и регистрации | Клиентская часть |
| features/admin | `<<source>>` | Интерфейс администратора для просмотра, создания и удаления лабиринтов | Клиентская часть |
| features/player | `<<source>>` | Интерфейс игрока для выбора, ручного прохождения и автоматического решения лабиринтов | Клиентская часть |
| shared/api | `<<source>>` | REST JSON API-клиент frontend | Клиентская часть |
| shared/types | `<<source>>` | Общие TypeScript-типы домена и API, используемые frontend и backend как контракт данных | Общие компоненты |
| NestJS backend API | `<<executable>>` | Серверная часть приложения | Серверная часть |
| AuthModule | `<<source>>` | Аутентификация, регистрация, выход и получение текущего пользователя | Серверная часть |
| UsersModule | `<<source>>` | Работа с пользователями | Серверная часть |
| LabyrinthsModule | `<<source>>` | Операции со списком, созданием, удалением, деталями и решением лабиринтов | Серверная часть |
| GenerationModule | `<<source>>` | Генерация лабиринтов алгоритмами Прима и Краскала | Серверная часть |
| SolvingModule | `<<source>>` | Поиск пути в лабиринте алгоритмами BFS и DFS | Серверная часть |
| Prisma Client | `<<library>>` | Программный слой доступа backend к PostgreSQL | Серверная часть / слой данных |
| PostgreSQL | `<<executable>>` | Хранение данных о пользователях и лабиринтах | Слой данных |

**Примечание для вставки в docx.** Номер рисунка `N` и номер таблицы необходимо заменить при ручном переносе секции в `report/ours.docx` с учётом итоговой нумерации пояснительной записки.
