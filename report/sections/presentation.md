## План презентации

Презентация к защите курсового проекта по системе «Лабиринт». Рекомендуемый объём — 15 слайдов. Для каждого слайда указаны заголовок, основные тезисы и графический материал из репозитория проекта.

### Слайд 1. Титульный

- Тема: «Разработка web-системы «Лабиринт» для генерации и прохождения двумерных лабиринтов».
- Дисциплина: «Программная инженерия», Самарский университет, 6 семестр.
- Авторы: Сидоров, Фокин.
- Руководитель: указать ФИО руководителя дисциплины.

### Слайд 2. Актуальность

- Лабиринты — классическая среда тестирования алгоритмов маршрутизации и искусственного интеллекта.
- Задачи генерации и прохождения остаются востребованными в учебной и прикладной разработке.
- Система объединяет в одном web-приложении математические алгоритмы построения и поиска пути и современную визуализацию.

### Слайд 3. Цель и задачи

- **Цель:** разработать web-систему генерации, хранения и прохождения двумерных толстостенных лабиринтов с разделением ролей администратора и игрока.
- **Задачи:**
  - анализ предметной области и существующих систем-аналогов;
  - проектирование архитектуры и информационно-логического проекта;
  - разработка и описание алгоритмов обработки данных;
  - реализация клиентской и серверной частей;
  - формирование документации и руководства пользователя.

### Слайд 4. Системы-аналоги

- Рассмотрены три системы: набор демонстраций алгоритмов генерации, отдельное приложение для построения лабиринтов и web-приложение для визуализации поиска пути.
- Сводная таблица сравнения по показателям: интерфейс, размеры, темы оформления, выбор алгоритма генерации, выбор алгоритма поиска пути, ручное прохождение, автоматическое прохождение.
- Вывод: совмещение генерации, ручного прохождения и автоматического решения в одной системе — ниша разрабатываемой системы.

### Слайд 5. Диаграмма объектов предметной области

- Рисунок: `diagrams/object/object.png`.
- Центральная сущность — Лабиринт; связан с Сеткой, Клетками, Темой оформления, Алгоритмом генерации и Алгоритмом поиска пути.
- Пользователь имеет роль Администратора или Игрока. Администратор создаёт лабиринты, игрок проходит.

### Слайд 6. Диаграмма вариантов использования

- Рисунок: `diagrams/use-case/use-case.png`.
- Три актёра: Пользователь, Администратор, Игрок.
- Ключевые use case: авторизация, регистрация, создание лабиринта (с подпунктами), удаление лабиринта, ручное прохождение, автоматическое решение, смена темы, справка.

### Слайд 7. Структурная схема системы

- Рисунок: `diagrams/structure/structure.png`.
- Клиентская часть: подсистемы авторизации, администратора, игрока, визуализации, справки, взаимодействия с сервером.
- Серверная часть: подсистемы взаимодействия с клиентом, аутентификации, работы с пользователями, работы с лабиринтами (генерация / поиск / валидация), взаимодействия с СУБД.
- Связь — по HTTP/REST поверх HTTPS.

### Слайд 8. Диаграммы состояний и последовательности

- Рисунки: `diagrams/state/general.png`, `diagrams/state/admin.png`, `diagrams/state/player.png`, `diagrams/sequence/name-input.png`, `diagrams/sequence/theme-change.png`.
- Обобщённая state diagram + два подавтомата (Администратор и Игрок).
- Два sequence-сценария: «Ввести название лабиринта» и «Изменить тему оформления».

### Слайд 9. Диаграммы реализации

- Рисунки: `diagrams/components/component-diagram.png`, `diagrams/deployment/deployment-diagram.png`, `diagrams/class/class-diagram.png`.
- Компонентная диаграмма: модули React-клиента + модули NestJS-сервера + Prisma Client.
- Развёртывание: клиентский узел (браузер) — сеть Интернет — серверный узел (Node.js + PostgreSQL).
- Диаграмма классов: основные доменные классы серверной части.

### Слайд 10. Модели данных

- Рисунки: `diagrams/data/logical-data-model.png`, `diagrams/data/physical-data-model.png`.
- Логическая модель: сущности `Пользователь`, `Лабиринт`, перечисления роли, темы, алгоритма, режима расстановки входа и выхода.
- Физическая модель: таблицы `User`, `Labyrinth` в PostgreSQL; внешний ключ `createdById`, составной индекс по `deletedAt`, `createdAt`, `id`, поле `grid` типа JSON.

### Слайд 11. Алгоритмы Прима и волнового поиска пути

- Рисунки: `diagrams/algorithms/prim.png`, `diagrams/algorithms/bfs.png`.
- Метод Прима: остовное дерево проходов на сетке; случайный выбор фронтира на каждой итерации; пробивание стены между текущей и целевой клетками.
- Волновой алгоритм: поиск в ширину; очередь, множество посещённых, карта предков; восстановление пути обратным проходом.
- Также реализованы метод Краскала и метод правой руки — они приведены в Приложении Б.

### Слайд 12. Технологический стек

- **Клиентская часть:** TypeScript 5.9, React 19, Vite 7, react-router-dom.
- **Серверная часть:** TypeScript 5.9, Node.js 22, NestJS 11, Prisma ORM, JWT-авторизация в cookie.
- **База данных:** PostgreSQL 16.
- **Инфраструктура:** Docker 24 для локального запуска БД, npm 10 для управления зависимостями.
- **Проектные артефакты:** PlantUML для UML-диаграмм и блок-схем алгоритмов, Git/GitHub для контроля версий.

### Слайд 13. Демонстрация интерфейса

- 4 скриншота: `report/images/auth.png`, `report/images/admin-list.png`, `report/images/create-editor-generated.png`, `report/images/player-auto-solve.png`.
- Кратко: вход → список лабиринтов → редактор → автоматическое решение.

### Слайд 14. Минимальные технические требования

- **Рабочее место клиента:** ОЗУ ≥ 4 Гб, диск ≥ 25 Гб, монитор ≥ 1280 × 720, актуальный Chrome / Firefox / Safari, ОС Windows 10 / macOS 12 / Linux Ubuntu 22.04.
- **Сервер:** ОЗУ ≥ 2 Гб, диск ≥ 20 Гб, 2 ядра ≥ 2,2 ГГц, Linux Ubuntu Server 22.04, Node.js 22, PostgreSQL 16, Docker 24, публичный IP-адрес.
- Расчёт памяти: клиентская часть ≈ 20,9 Гб внешней и ≈ 3 Гб ОЗУ; серверная часть ≈ 7,3 Гб внешней и ≈ 2 Гб ОЗУ.

### Слайд 15. Заключение и перспективы развития

- Разработана web-система «Лабиринт» с двумя ролями пользователей — администратора и игрока.
- Реализованы 2 алгоритма генерации (Прима, Краскала) и 2 алгоритма поиска пути (волновой, метод правой руки).
- Подготовлены все канонические UML-диаграммы, схемы алгоритмов, модели данных и руководство пользователя.
- **Перспективы развития:** расширение набора алгоритмов поиска пути (A*, Дейкстра); поддержка лабиринтов большего размера и нестандартных форм; режим соревнования между игроками с рейтингом по времени прохождения.
- Спасибо за внимание!
