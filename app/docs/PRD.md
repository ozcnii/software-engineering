# PRD: Лабиринт

## 1. Назначение продукта

«Лабиринт» — веб-приложение для создания, визуализации и прохождения двумерных толстостенных лабиринтов. Система поддерживает две основные роли:

- Администратор создаёт, просматривает и удаляет лабиринты.
- Игрок выбирает лабиринт, проходит его вручную или запускает автоматическое решение.

Продукт должен соответствовать функционалу, заложенному в HTML-прототипе `sandbox/index.html`, use-case диаграмме, диаграммам состояний и сценариям курсового проекта.

## 2. Роли пользователей

### Пользователь

Базовая роль до входа в систему. Может:

- открыть форму входа;
- открыть форму регистрации;
- ввести логин и пароль;
- при регистрации ввести подтверждение пароля;
- получить ошибку валидации при некорректных данных.

### Администратор

Пользователь с правом управления лабиринтами. Может:

- просматривать список всех лабиринтов;
- искать лабиринт по названию;
- создавать новый лабиринт через мастер из трёх шагов;
- редактировать структуру лабиринта на холсте во время создания;
- удалять лабиринт после подтверждения;
- просматривать сведения о системе и разработчике;
- выйти из системы.

### Игрок

Пользователь с правом прохождения лабиринтов. Может:

- просматривать список доступных лабиринтов;
- искать лабиринт по названию;
- выбирать лабиринт из списка;
- менять тему оформления локально для текущей сессии;
- проходить лабиринт вручную;
- запускать автоматическое решение волновым алгоритмом или методом правой руки;
- выбирать режим отображения авто-решения;
- настраивать скорость анимации;
- сбрасывать прохождение;
- выходить из уровня;
- просматривать сведения о системе и разработчике;
- выйти из системы.

## 3. Основные сущности

### User

Поля:

- `id` — уникальный идентификатор пользователя.
- `login` — логин, от 4 до 8 символов.
- `passwordHash` — хеш пароля, исходный пароль не хранится.
- `role` — `admin` или `player`.
- `createdAt` — дата регистрации.

Администратор не создаётся через публичную регистрацию. Начальная учётная запись администратора создаётся seed-скриптом при подготовке базы данных. Публичная регистрация создаёт только пользователей с ролью `player`.

### Labyrinth

Поля:

- `id` — уникальный идентификатор лабиринта.
- `name` — название лабиринта.
- `width` — нечётная ширина от 7 до 25.
- `height` — нечётная высота от 7 до 25.
- `theme` — `winter`, `summer`, `autumn` или `spring`.
- `generationAlgorithm` — `prim` или `kruskal`.
- `entryMode` — `auto` или `manual`.
- `entry` — координаты входа.
- `exit` — координаты выхода.
- `grid` — двумерная матрица ячеек лабиринта.
- `createdBy` — идентификатор администратора.
- `createdAt` — дата создания.

В списках лабиринтов дополнительно возвращается вычисляемое поле `difficulty`. Оно не хранится в базе данных и рассчитывается по максимальной стороне лабиринта:

- `1` — `max(width, height) <= 7`;
- `2` — `max(width, height)` от 9 до 13;
- `3` — `max(width, height)` от 15 до 25.

### Maze Cell

Каждая ячейка сетки имеет тип:

- `wall` — стена;
- `path` — проход;
- `entry` — вход;
- `exit` — выход.

Вход и выход должны располагаться на периметре, не должны находиться в углах и не должны совпадать.

## 4. Пользовательские сценарии

### Вход

1. Пользователь открывает экран аутентификации.
2. Выбирает вкладку «Вход».
3. Вводит логин и пароль.
4. Система проверяет заполненность и длину полей.
5. Система проверяет пользователя в базе.
6. При успехе открывается экран в соответствии с ролью.
7. При ошибке пользователь остаётся на форме и видит сообщение рядом с некорректным полем.

### Регистрация

1. Пользователь выбирает вкладку «Регистрация».
2. Вводит логин, пароль и подтверждение пароля.
3. Система проверяет поля.
4. При успехе создаётся пользователь.
5. После успешной регистрации пользователь попадает в приложение с ролью игрока.

### Создание лабиринта администратором

1. Администратор открывает пункт «Создать новый».
2. На шаге «Параметры» вводит название, размеры, тему, способ расстановки входа/выхода и алгоритм генерации.
3. Нажимает «Далее — Сгенерировать».
4. Система валидирует параметры.
5. Система генерирует лабиринт и открывает шаг «Редактор».
6. Администратор может менять стены, проходы, вход и выход.
7. Администратор может перегенерировать лабиринт.
8. После проверки входа и выхода администратор переходит к шагу «Сохранить».
9. Система показывает итоговые параметры и превью.
10. Администратор сохраняет лабиринт.
11. Система возвращает администратора к списку лабиринтов.

### Удаление лабиринта

1. Администратор открывает список лабиринтов.
2. Нажимает кнопку удаления у выбранного лабиринта.
3. Система показывает модальное окно подтверждения.
4. При отмене список не меняется.
5. При подтверждении лабиринт удаляется, список обновляется.

### Прохождение вручную

1. Игрок выбирает лабиринт из списка.
2. Система загружает лабиринт и ставит игрока во входную точку.
3. Игрок выбирает вкладку «Ручное».
4. Игрок перемещается стрелками клавиатуры или кнопками d-pad.
5. Система разрешает ход только по проходам.
6. Система отображает текущую позицию, след пути, количество шагов и время.
7. При достижении выхода система показывает завершение уровня.

### Автоматическое прохождение

1. Игрок выбирает лабиринт.
2. Открывает вкладку «Авто-решение».
3. Выбирает волновой алгоритм или метод правой руки.
4. Выбирает режим: с анимацией или мгновенный результат.
5. В режиме анимации задаёт скорость от 1 до 10 шагов в секунду.
6. Нажимает «Запустить решение».
7. Система находит путь и отображает его на лабиринте.
8. Волновой алгоритм должен возвращать кратчайший путь по количеству шагов.
9. Метод правой руки должен возвращать путь, если он достигает выхода без цикла.

## 5. Экран авторизации и регистрации

Экран содержит:

- название приложения «Лабиринт»;
- подпись «система генерации и прохождения лабиринтов»;
- вкладки «Вход» и «Регистрация»;
- форму входа с полями логина и пароля;
- форму регистрации с полями логина, пароля и подтверждения пароля.

Правила валидации:

- логин обязателен;
- длина логина: от 4 до 8 символов;
- пароль обязателен;
- длина пароля: от 4 до 10 символов;
- подтверждение пароля обязательно при регистрации;
- пароль и подтверждение должны совпадать;
- принятие условий обязательно при регистрации.

## 6. Экран администратора

Экран администратора состоит из:

- верхней панели с названием приложения, ролью, именем пользователя и кнопкой выхода;
- левого меню;
- основной рабочей области.

Пункты меню:

- «Все лабиринты»;
- «Создать новый»;
- «Справка».

### Список лабиринтов

Список отображает таблицу с колонками:

- название;
- размер;
- алгоритм генерации;
- тема;
- действия.

В списке должна быть строка поиска. Фильтрация выполняется по названию лабиринта.

### Удаление

Удаление всегда требует подтверждения в модальном окне. В окне отображается название выбранного лабиринта. Кнопка «Отмена» закрывает окно без изменений. Кнопка подтверждения удаляет лабиринт.

## 7. Создание и редактирование лабиринта

Мастер создания состоит из трёх шагов.

### Шаг 1. Параметры

Поля и настройки:

- «Название лабиринта»;
- «Ширина»;
- «Высота»;
- «Тема оформления»;
- «Вход и выход»;
- «Алгоритм генерации».

Правила:

- название обязательно;
- ширина и высота должны быть нечётными числами от 7 до 25;
- доступные темы: зима, лето, осень, весна;
- доступные алгоритмы генерации: Прима и Краскала;
- доступные режимы входа/выхода: авто и вручную.

Если название пустое, система показывает сообщение «Введите название лабиринта». При других некорректных параметрах система остаётся на шаге параметров и показывает ошибку рядом с соответствующим полем.

### Шаг 2. Редактор

Редактор содержит:

- холст лабиринта;
- инструмент «Стена»;
- инструмент «Проход»;
- инструмент «Вход»;
- инструмент «Выход»;
- действия «Отмена» и «Повтор» для правок редактора;
- кнопку «Перегенерировать»;
- блок параметров;
- блок статуса входа и выхода;
- легенду ячеек.

При ручной расстановке вход и выход задаёт администратор. При автоматической расстановке система выбирает вход и выход на периметре.

Переход к шагу сохранения разрешён только когда вход и выход заданы и валидны.

### Шаг 3. Сохранение

Система отображает:

- превью лабиринта;
- название;
- размер;
- тему;
- алгоритм;
- статус входа и выхода.

Кнопка «Сохранить лабиринт» сохраняет лабиринт. Кнопка «Отмена» возвращает администратора к списку без сохранения.

## 8. Экран игрока

Экран игрока состоит из:

- верхней панели с названием приложения, ролью, именем пользователя и кнопкой выхода;
- левой панели выбора лабиринта;
- центральной области визуализации;
- правой панели статистики и действий;
- нижней строки состояния.

### Выбор лабиринта

Левая панель содержит:

- список лабиринтов;
- поиск;
- название, размер, алгоритм, тему и вычисленную сложность каждого лабиринта;
- блок выбора темы;
- ссылку на страницу «Справка».

После выбора лабиринта система загружает его в центральную область.

### Тема оформления

Игрок может выбрать одну из тем:

- зима;
- лето;
- осень;
- весна.

Смена темы действует только в текущей сессии игрока и не изменяет сохранённую тему лабиринта. При выходе из уровня тема сбрасывается к теме, сохранённой у лабиринта.

### Ручное управление

Игрок может перемещаться:

- стрелками клавиатуры;
- кнопками d-pad на экране.

Ход в стену не меняет позицию игрока. Успешный ход увеличивает счётчик шагов и добавляет клетку в след прохождения.

### Авто-решение

Игрок может выбрать:

- волновой алгоритм — кратчайший путь;
- метод правой руки — движение вдоль стены;
- режим «С анимацией»;
- режим «Мгновенный результат»;
- скорость анимации от 1 до 10 шагов в секунду.

В режиме мгновенного результата используется волновой алгоритм, настройка скорости не используется.

### Статистика и действия

Правая панель показывает:

- количество шагов;
- время прохождения.

Доступные действия:

- «Сбросить» — вернуть игрока на старт, очистить путь и статистику текущей попытки;
- «Выйти из уровня» — вернуться к выбору лабиринта.

## 9. Алгоритмы генерации и поиска пути

### Алгоритм Прима

Генерирует связный лабиринт с равномерным распределением проходов и короткими тупиками. Итоговая сетка должна иметь достижимый путь от входа к выходу.

### Алгоритм Краскала

Генерирует связный лабиринт с более хаотичной структурой и длинными коридорами. Итоговая сетка должна иметь достижимый путь от входа к выходу.

### Волновой алгоритм

Используется для поиска кратчайшего пути. Если путь существует, результат должен содержать последовательность координат от входа к выходу с минимальным количеством шагов.

### Метод правой руки

Используется для прохождения вдоль правой стены. Если алгоритм достигает выхода без повторения состояния, результат должен содержать последовательность координат от входа к выходу; путь не обязан быть кратчайшим.

## 10. Темы оформления

Система поддерживает четыре темы:

- `winter` — Зима;
- `summer` — Лето;
- `autumn` — Осень;
- `spring` — Весна.

Тема влияет только на визуальное отображение лабиринта. Структура лабиринта, координаты входа и выхода, прогресс игрока и результаты алгоритмов не должны зависеть от темы.

## 11. REST JSON API

API использует JSON-запросы и JSON-ответы. Ошибки возвращаются в едином формате:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Описание ошибки",
    "fields": {
      "fieldName": "Описание ошибки поля"
    }
  }
}
```

### POST /api/auth/login

Назначение: вход пользователя.

Запрос:

```json
{
  "login": "ivan",
  "password": "1234"
}
```

Ответ 200:

```json
{
  "user": {
    "id": "user-1",
    "login": "ivan",
    "role": "admin"
  }
}
```

Ошибки: `VALIDATION_ERROR`, `INVALID_CREDENTIALS`.

### POST /api/auth/register

Назначение: регистрация пользователя.

Запрос:

```json
{
  "login": "maria",
  "password": "1234",
  "passwordConfirm": "1234"
}
```

Роль в запросе не передаётся. Система всегда создаёт пользователя с ролью `player`.

Ответ 201:

```json
{
  "user": {
    "id": "user-2",
    "login": "maria",
    "role": "player"
  }
}
```

Ошибки: `VALIDATION_ERROR`, `LOGIN_ALREADY_EXISTS`.

### POST /api/auth/logout

Назначение: выход из системы.

Ответ 204: тело ответа отсутствует.

### GET /api/labyrinths

Назначение: получить список лабиринтов.

Query-параметры:

- `search` — необязательная строка поиска по названию.

```json

  "items": [

      "id": "lab-1",
```

## 12. Ошибки, пустые состояния и ограничения

Обязательные состояния:

- пустой список лабиринтов у администратора;
- пустой список лабиринтов у игрока;
- отсутствие результатов поиска;
- ошибка входа при неверном логине или пароле;
- ошибка регистрации при занятом логине;
- ошибка регистрации при несовпадающих паролях;
- отсутствие seed-администратора при попытке входа в роль администратора;
- ошибка создания лабиринта при пустом названии;
- ошибка создания лабиринта при чётной ширине или высоте;
- ошибка создания лабиринта при размере меньше 7 или больше 25;
- ошибка перехода к сохранению, если вход или выход не заданы;
- ошибка авто-решения, если путь не найден.

Ограничения:

- игрок не может создавать, сохранять и удалять лабиринты;
- администратор не проходит лабиринты на экране администратора;
- публичная регистрация не создаёт администраторов;
- тема игрока не сохраняется в базе данных;
- сложность лабиринта не хранится в базе данных, а вычисляется при выдаче списка;
- пароль не возвращается в API-ответах;
- удаление лабиринта необратимо после подтверждения.

## 13. Критерии готовности

Реализация считается соответствующей PRD, если:

- реализованы экраны входа, регистрации, администратора и игрока;
- роли разделяют доступ к функциям;
- администратор может создать, найти и удалить лабиринт;
- мастер создания проходит все три шага;
- лабиринты сохраняются и загружаются через backend;
- игрок может выбрать лабиринт и пройти его вручную;
- волновой алгоритм возвращает кратчайший путь;
- метод правой руки возвращает путь при достижении выхода без цикла;
- смена темы у игрока действует только в текущей сессии;
- ошибки и пустые состояния отображаются пользователю;
- REST JSON API соответствует разделу 11;
- все сценарии из `app/docs/CHECKLIST.md` проходят.
