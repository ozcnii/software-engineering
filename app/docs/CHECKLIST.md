# Implementation Checklist

Этот файл используется для проверки реализации приложения «Лабиринт» по `app/docs/PRD.md`.

Формат результата для каждого пункта:

- `PASS` — поведение полностью совпадает с ожидаемым.
- `FAIL` — поведение не совпадает с ожидаемым.
- `BLOCKED` — пункт нельзя проверить из-за отсутствующей зависимости или недоступного окружения.

## 1. Auth

### AUTH-01. Открывается экран входа

Шаги:

1. Открыть приложение.
2. Убедиться, что активна вкладка «Вход».

Ожидаемый результат:

- отображается название «Лабиринт»;
- отображаются вкладки «Вход» и «Регистрация»;
- отображаются поля «Логин» и «Пароль»;
- отображается кнопка входа.

### AUTH-02. Пустой вход не проходит

Шаги:

1. Открыть вкладку «Вход».
2. Оставить логин и пароль пустыми.
3. Нажать кнопку входа.

Ожидаемый результат:

- пользователь остаётся на форме входа;
- рядом с логином показана ошибка «Введите логин»;
- рядом с паролем показана ошибка «Введите пароль».

### AUTH-03. Валидация длины логина и пароля при входе

Шаги:

1. Ввести логин короче 4 символов.
2. Ввести пароль короче 4 символов.
3. Нажать кнопку входа.

Ожидаемый результат:

- пользователь остаётся на форме входа;
- показана ошибка про длину логина от 4 до 8 символов;
- показана ошибка про длину пароля от 4 до 10 символов.

### AUTH-04. Успешный вход открывает экран по роли

Шаги:

1. Подготовить базу данных seed-скриптом с начальной учётной записью администратора.
2. Ввести корректный логин и пароль администратора.
3. Нажать кнопку входа.
4. Повторить проверку для пользователя с ролью игрока.

Ожидаемый результат:

- администратор попадает на экран администратора;
- игрок попадает на экран игрока;
- в интерфейсе отображается соответствующая роль.

### AUTH-05. Регистрация требует обязательные поля

Шаги:

1. Открыть вкладку «Регистрация».
2. Оставить все поля пустыми.
3. Не принимать условия использования.
4. Нажать кнопку регистрации.

Ожидаемый результат:

- пользователь остаётся на форме регистрации;
- показаны ошибки для логина, пароля, подтверждения пароля и условий использования.

### AUTH-06. Регистрация проверяет совпадение паролей

Шаги:

1. Открыть вкладку «Регистрация».
2. Ввести корректный логин.
3. Ввести пароль.
4. Ввести другое значение в подтверждение пароля.
5. Принять условия использования.
6. Нажать кнопку регистрации.

Ожидаемый результат:

- пользователь остаётся на форме регистрации;
- показана ошибка «Пароли не совпадают».

### AUTH-07. Успешная регистрация создаёт игрока

Шаги:

1. Открыть вкладку «Регистрация».
2. Ввести логин длиной 4-8 символов.
3. Ввести пароль длиной 4-10 символов.
4. Повторить пароль.
5. Принять условия использования.
6. Нажать кнопку регистрации.

Ожидаемый результат:

- пользователь создан;
- пользователь попадает в приложение с ролью игрока;
- пароль не отображается в интерфейсе и не возвращается API.
- регистрация не даёт пользователю роль администратора.

## 2. Admin: список лабиринтов

### ADM-LIST-01. Администратор видит список лабиринтов

Шаги:

1. Войти как администратор.
2. Открыть пункт «Все лабиринты».

Ожидаемый результат:

- отображается таблица лабиринтов;
- есть колонки «Название», «Размер», «Алгоритм», «Тема» и колонка действий;
- есть поле поиска;
- есть кнопка создания нового лабиринта.

### ADM-LIST-02. Поиск фильтрует список

Шаги:

1. Открыть список лабиринтов.
2. Ввести часть существующего названия в поиск.

Ожидаемый результат:

- в таблице остаются только лабиринты, название которых соответствует поиску.

### ADM-LIST-03. Пустой результат поиска отображается явно

Шаги:

1. Открыть список лабиринтов.
2. Ввести строку, которой нет ни в одном названии.

Ожидаемый результат:

- таблица не показывает неподходящие записи;
- пользователь видит состояние «ничего не найдено» или равнозначное сообщение.

### ADM-LIST-04. Игрок не имеет доступа к админскому списку

Шаги:

1. Войти как игрок.
2. Попробовать открыть экран или API списка управления лабиринтами администратора.

Ожидаемый результат:

- игрок не получает доступ к функциям создания и удаления;
- backend возвращает ошибку доступа для административных операций.

## 3. Admin: создание лабиринта

### ADM-CREATE-01. Открывается мастер создания

Шаги:

1. Войти как администратор.
2. Нажать «Создать новый».

Ожидаемый результат:

- открыт экран «Создать лабиринт»;
- виден степпер из трёх шагов: «Параметры», «Редактор», «Сохранить»;
- активен шаг «Параметры».

### ADM-CREATE-02. Шаг параметров содержит все поля

Шаги:

1. Открыть мастер создания.

Ожидаемый результат:

- есть поле «Название лабиринта»;
- есть поля «Ширина» и «Высота»;
- доступны темы «Зима», «Лето», «Осень», «Весна»;
- доступны режимы входа и выхода «Авто» и «Вручную»;
- доступны алгоритмы «Прима» и «Краскала».

### ADM-CREATE-03. Пустое название блокирует генерацию

Шаги:

1. Открыть мастер создания.
2. Оставить название пустым.
3. Нажать «Далее — Сгенерировать».

Ожидаемый результат:

- переход к редактору не происходит;
- показано сообщение «Введите название лабиринта».

### ADM-CREATE-04. Невалидный размер блокирует генерацию

Шаги:

1. Открыть мастер создания.
2. Ввести корректное название.
3. Ввести чётную ширину или высоту.
4. Нажать «Далее — Сгенерировать».
5. Повторить с размером меньше 7.
6. Повторить с размером больше 25.

Ожидаемый результат:

- переход к редактору не происходит;
- пользователь видит ошибку размера;
- валидными считаются только нечётные значения от 7 до 25.

### ADM-CREATE-05. Валидные параметры открывают редактор

Шаги:

1. Ввести название.
2. Указать нечётную ширину и высоту от 7 до 25.
3. Выбрать тему.
4. Выбрать режим входа/выхода.
5. Выбрать алгоритм генерации.
6. Нажать «Далее — Сгенерировать».

Ожидаемый результат:

- открыт шаг «Редактор»;
- на холсте отображён лабиринт выбранного размера;
- в блоке параметров отображаются выбранные значения.

### ADM-CREATE-06. Редактор содержит нужные инструменты

Шаги:

1. Открыть шаг «Редактор».

Ожидаемый результат:

- доступны инструменты «Стена», «Проход», «Вход», «Выход»;
- доступна кнопка «Перегенерировать»;
- отображается статус входа и выхода;
- отображается легенда ячеек.

### ADM-CREATE-07. Перегенерация меняет лабиринт без сброса параметров

Шаги:

1. Открыть шаг «Редактор».
2. Запомнить выбранные параметры.
3. Нажать «Перегенерировать».

Ожидаемый результат:

- структура лабиринта обновляется;
- название, размер, тема и алгоритм остаются теми же.

### ADM-CREATE-08. Нельзя сохранить без входа и выхода

Шаги:

1. Открыть шаг «Редактор».
2. Удалить или не задать вход или выход.
3. Нажать переход к шагу «Сохранить».

Ожидаемый результат:

- переход к сохранению не происходит;
- пользователь видит, что вход или выход не задан.

### ADM-CREATE-09. Сохранение создаёт лабиринт

Шаги:

1. Создать валидный лабиринт.
2. Перейти на шаг «Сохранить».
3. Проверить превью и итоговые параметры.
4. Нажать «Сохранить лабиринт».

Ожидаемый результат:

- лабиринт сохранён;
- пользователь возвращается к списку;
- новый лабиринт отображается в списке.

### ADM-CREATE-10. Отмена не сохраняет черновик

Шаги:

1. Открыть мастер создания.
2. Ввести параметры.
3. Нажать «Отмена».

Ожидаемый результат:

- пользователь возвращается к списку;
- новый лабиринт не появляется в списке.

### ADM-DELETE-02. Отмена закрывает окно без удаления

Шаги:

2. Нажать «Отмена».

Ожидаемый результат:

- окно закрывается;

Шаги:

Ожидаемый результат:

## 5. Player: выбор и прохождение

### PLAYER-01. Игрок видит экран игрока

Шаги:

1. Войти как игрок.

Ожидаемый результат:

- отображается экран игрока;
- видна левая панель выбора лабиринта;
- видна центральная область лабиринта;
- видна правая панель статистики;
- видна нижняя строка состояния.

### PLAYER-02. Поиск фильтрует лабиринты

Шаги:

1. Открыть экран игрока.
2. Ввести часть названия в поиск.

Ожидаемый результат:

- список показывает только подходящие лабиринты.

### PLAYER-03. Выбор лабиринта загружает уровень

Шаги:

1. Открыть экран игрока.
2. Нажать на лабиринт в списке.

Ожидаемый результат:

- выбранный лабиринт отображается в центре;
- игрок находится на входе;
- статус показывает, что уровень активен.

### PLAYER-04. Смена темы локальна для сессии

Шаги:

1. Выбрать лабиринт.
2. Сменить тему в левой панели.
3. Выйти из уровня.
4. Снова выбрать тот же лабиринт.

Ожидаемый результат:

- визуализация меняется сразу после выбора темы;
- сохранённая тема лабиринта не меняется;
- после повторного входа тема сброшена к теме лабиринта.

### PLAYER-05. Ручное движение по проходу

Шаги:

1. Выбрать лабиринт.
2. Открыть вкладку «Ручное».
3. Сделать ход в соседний проход стрелкой или d-pad.

Ожидаемый результат:

- позиция игрока меняется;
- счётчик шагов увеличивается;
- след пути отображается на лабиринте.

### PLAYER-06. Ручное движение в стену блокируется

Шаги:

1. Выбрать лабиринт.
2. Сделать ход в сторону стены.

Ожидаемый результат:

- позиция игрока не меняется;
- ход не должен считаться успешным.

### PLAYER-07. Сброс возвращает игрока на старт

Шаги:

1. Выбрать лабиринт.
2. Сделать несколько ходов.
3. Нажать «Сбросить».

Ожидаемый результат:

- игрок возвращается на вход;
- след пути очищается;
- статистика текущей попытки сбрасывается.

### PLAYER-08. Выход из уровня возвращает к выбору

Шаги:

1. Выбрать лабиринт.
2. Нажать «Выйти из уровня».

Ожидаемый результат:

- активный уровень закрывается;
- игрок возвращается к выбору лабиринта;
- локально выбранная тема сбрасывается.

## 6. Player: авто-решение

### AUTO-01. Открывается вкладка авто-решения

Шаги:

1. Выбрать лабиринт.
2. Открыть вкладку «Авто-решение».

Ожидаемый результат:

- отображается выбор BFS и DFS;
- отображается выбор режима «С анимацией» и «Мгновенный результат»;
- в режиме анимации отображается настройка скорости.

### AUTO-02. Мгновенный режим скрывает скорость

Шаги:

1. Открыть вкладку «Авто-решение».
2. Выбрать «Мгновенный результат».

Ожидаемый результат:

- настройка скорости не отображается или не используется.

### AUTO-03. BFS строит кратчайший путь

Шаги:

1. Выбрать лабиринт с известным кратчайшим путём.
2. Открыть «Авто-решение».
3. Выбрать BFS.
4. Запустить решение.

Ожидаемый результат:

- система отображает путь от входа к выходу;
- путь проходит только по проходам;
- количество шагов равно длине кратчайшего пути.

### AUTO-04. DFS строит допустимый путь

Шаги:

1. Выбрать лабиринт с существующим путём.
2. Открыть «Авто-решение».
3. Выбрать DFS.
4. Запустить решение.

Ожидаемый результат:

- система отображает путь от входа к выходу;
- путь проходит только по проходам;
- путь не обязан быть кратчайшим.

### AUTO-05. Анимация учитывает скорость

Шаги:

1. Открыть «Авто-решение».
2. Выбрать режим «С анимацией».
3. Установить скорость 1 шаг/сек.
4. Запустить решение.
5. Повторить со скоростью 10 шагов/сек.

Ожидаемый результат:

- при скорости 1 шаг/сек путь отображается медленнее;
- при скорости 10 шагов/сек путь отображается быстрее.

## 8. API checks

### API-01. Login API

Запрос:

```http
POST /api/auth/login
Content-Type: application/json

{
  "login": "ivan",
  "password": "1234"
}
```

Ожидаемый результат:

- статус `200`;
- в ответе есть `user.id`, `user.login`, `user.role`;
- в ответе нет пароля.

### API-02. Register API

Запрос:

```http
POST /api/auth/register
Content-Type: application/json

{
  "login": "maria",
  "password": "1234",
  "passwordConfirm": "1234",
  "acceptedTerms": true
}
```

Ожидаемый результат:

- статус `201`;
- создан пользователь с ролью `player`;
- роль администратора через публичную регистрацию создать нельзя;
- в ответе нет пароля.

### API-03. Labyrinth list API

Запрос:

```http
GET /api/labyrinths
```

Ожидаемый результат:

- статус `200`;
- ответ содержит массив `items`;
- каждый элемент содержит `id`, `name`, `width`, `height`, `theme`, `generationAlgorithm`, `difficulty`;
- `difficulty` вычисляется из максимальной стороны лабиринта: 7 — `1`, 9-13 — `2`, 15-25 — `3`.

### API-04. Labyrinth search API

Запрос:

```http
GET /api/labyrinths?search=mini
```

Ожидаемый результат:

- статус `200`;
- в `items` возвращаются только лабиринты, подходящие под поиск по названию.

### API-05. Generate API

Запрос:

```http
POST /api/labyrinths/generate
Content-Type: application/json

{
  "width": 11,
  "height": 11,
  "theme": "winter",
  "generationAlgorithm": "prim",
  "entryMode": "auto"
}
```

Ожидаемый результат:

- статус `200`;
- ответ содержит `grid`, `entry`, `exit`;
- `entry` и `exit` находятся на периметре;
- `entry` и `exit` не совпадают;
- существует путь от `entry` до `exit`.

### API-06. Create Labyrinth API

Запрос:

```http
POST /api/labyrinths
Content-Type: application/json

{
  "name": "Мини 7x7",
  "width": 7,
  "height": 7,
  "theme": "winter",
  "generationAlgorithm": "prim",
  "entryMode": "auto",
  "entry": { "row": 0, "col": 1 },
  "exit": { "row": 6, "col": 5 },
  "grid": [
```

Запрос:

```http

  "algorithm": "bfs"

```

- путь проходит только по проходам;

## 9. Итоговая приёмка

Реализация принимается по PRD, если:

- все пункты Auth имеют статус `PASS`;
- все пункты Admin имеют статус `PASS`;
- все пункты Player имеют статус `PASS`;
- все пункты API имеют статус `PASS`;
- все ограничения ролей соблюдаются;
- смена темы у игрока не сохраняется в базе;
- BFS возвращает кратчайший путь;
- DFS возвращает допустимый путь;
- ошибки отображаются пользователю и возвращаются API в согласованном формате.
